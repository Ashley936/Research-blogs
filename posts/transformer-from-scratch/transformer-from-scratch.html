Attention Is All You Need: A Transformer From Scratch, With an Honest Ablation

1. Introduction

Most people’s first contact with a Transformer these days is nn.TransformerEncoderLayer or a HuggingFace AutoModel. That’s the right call for shipping something — but it also means the internals stay a black box: the exact place dropout gets applied, why embeddings get scaled by √d_model, why the original paper’s learning rate schedule looks the way it does. This post is the opposite exercise: build the encoder-decoder Transformer from “Attention Is All You Need” (Vaswani et al., 2017) layer by layer, in plain PyTorch, and then use that implementation to actually test one of the architecture’s most consequential — and most under-explained — design choices: Pre-LN vs Post-LN, crossed with flat learning rate vs warmup+decay.

Scope: this is the original encoder-decoder machine-translation-style Transformer, not a decoder-only GPT-style model. That distinction matters later when we talk about cross-attention and masking.

By the end, you’ll have: - A full from-scratch implementation with every shape and design decision explained - A working mental model for why Pre-LN training is more stable than Post-LN - Empirical evidence (not just folklore) for how LR schedule interacts with normalization placement

This is the first post in a longer series — the next stops are KV caching, quantization (TurboQuant), and flow-matching-based generative models (DiT, F5-TTS), so I’ve tried to write the attention and masking sections in a way that will still be useful when we get to autoregressive decoding with a cache.

2. Architecture Overview

The Transformer is an encoder-decoder stack. The encoder maps an input sequence to a sequence of contextualized representations; the decoder generates an output sequence autoregressively, attending both to its own previous outputs (self-attention) and to the encoder’s output (cross-attention).

Input tokens → Embedding + PosEnc → [Encoder Layer × N] → Encoder Output
                                                                  │
Output tokens (shifted) → Embedding + PosEnc → [Decoder Layer × N] → Linear → Softmax
                                                        ▲
                                                        └── cross-attends to Encoder Output

Each encoder layer has two sub-layers: multi-head self-attention, then a position-wise feed-forward network. Each decoder layer has three: masked multi-head self-attention, multi-head cross-attention over the encoder output, then feed-forward. Every sub-layer is wrapped in a residual connection followed by layer normalization.

3. Input Representations

3.1 Token Embeddings and the √d_model Scale

Token IDs are mapped to d_model-dimensional vectors via a standard embedding table. The paper multiplies the embedding output by √d_model before adding positional encoding:

class InputEmbeddings(nn.Module):
    def __init__(self, d_model: int, vocab_size: int):
        super().__init__()
        self.d_model = d_model
        self.embedding = nn.Embedding(vocab_size, d_model)

    def forward(self, x):
        return self.embedding(x) * math.sqrt(self.d_model)

Why scale at all? The embedding table is typically initialized with small variance (roughly unit variance per dimension under standard init), while the sinusoidal positional encoding has values bounded in [-1, 1] with a specific frequency structure. Without scaling, the positional signal — which is fixed and not learned — would dominate the token embedding at initialization, and the model would have to spend early training just “fighting” the positional signal to extract token identity. Scaling by √d_model roughly matches the two signals’ magnitudes so gradients flow through both proportionally from step one. This is a paper-idiosyncratic choice; many later architectures (like GPT-2) drop this scaling because they use learned positional embeddings initialized at a compatible scale to begin with.

3.2 Sinusoidal Positional Encoding

class PositionalEncoding(nn.Module):
    def __init__(self, d_model: int, seq_len: int, dropout: float):
        super().__init__()
        self.dropout = nn.Dropout(dropout)
        pe = torch.zeros(seq_len, d_model)
        position = torch.arange(0, seq_len, dtype=torch.float).unsqueeze(1)
        div_term = torch.exp(torch.arange(0, d_model, 2).float() * (-math.log(10000.0) / d_model))
        pe[:, 0::2] = torch.sin(position * div_term)
        pe[:, 1::2] = torch.cos(position * div_term)
        pe = pe.unsqueeze(0)
        self.register_buffer('pe', pe)

    def forward(self, x):
        x = x + self.pe[:, :x.shape[1], :].requires_grad_(False)
        return self.dropout(x)

Why sin/cos instead of a learned positional embedding table? Two reasons the paper gives, and one practical one:

  1. Extrapolation: sinusoidal encodings are defined for any position, so the model can in principle handle sequences longer than anything seen during training (in practice this generalization is weak, but it’s non-zero, whereas a learned embedding table simply has no vector for position 513 if trained on length-512 sequences).
  2. Relative position as a linear function: for any fixed offset k, PE(pos+k) can be expressed as a linear transformation of PE(pos). This is because sin(a+b) and cos(a+b) expand into linear combinations of sin(a), cos(a), sin(b), cos(b). That means the model has an easy analytic handle for learning to attend by relative position, not just absolute position, if it’s useful for the task.
  3. No extra parameters — a genuinely minor but real practical benefit.

The div_term construction is the standard log-space trick to compute 10000^(2i/d_model) for each dimension pair without numerical overflow — take the log, scale, exponentiate.

4. Attention Mechanism

4.1 Scaled Dot-Product Attention

def attention(query, key, value, mask=None, dropout: nn.Dropout = None):
    d_k = query.shape[-1]
    attention_scores = (query @ key.transpose(-2, -1)) / math.sqrt(d_k)
    if mask is not None:
        attention_scores.masked_fill_(mask == 0, -1e9)
    attention_scores = attention_scores.softmax(dim=-1)
    if dropout is not None:
        attention_scores = dropout(attention_scores)
    return (attention_scores @ value), attention_scores

Why divide by √d_k? Assume query and key components are independent random variables with mean 0 and variance 1. The dot product q·k = Σ(q_i × k_i) over d_k terms has variance that grows linearly with d_k (variance of a sum of independent terms is the sum of variances, and each term q_i·k_i has variance 1 under these assumptions). So the raw dot product has variance ≈ d_k, meaning its typical magnitude grows with √d_k. Large-magnitude inputs to softmax push it into saturated regions where the gradient is near zero almost everywhere except at the max — the softmax becomes nearly a hard argmax and gradients vanish for all the non-selected positions. Dividing by √d_k renormalizes the dot product back to unit variance regardless of d_k, keeping softmax in a well-conditioned regime.

Masking: masked_fill_(mask == 0, -1e9) happens before softmax, not after. Setting scores to a large negative number (rather than zero) ensures that after softmax, those positions get a weight of essentially exp(-1e9) ≈ 0 — masking after softmax would just leave the wrong probabilities in place and require manual renormalization.

4.2 Multi-Head Attention

class MultiHeadAttentionBlock(nn.Module):
    def __init__(self, d_model: int, h: int, dropout: float):
        super().__init__()
        self.d_model = d_model
        self.h = h
        assert d_model % h == 0, "d_model must be divisible by h"
        self.d_k = d_model // h
        self.w_q = nn.Linear(d_model, d_model, bias=False)
        self.w_k = nn.Linear(d_model, d_model, bias=False)
        self.w_v = nn.Linear(d_model, d_model, bias=False)
        self.w_o = nn.Linear(d_model, d_model, bias=False)
        self.dropout = nn.Dropout(dropout)

    def forward(self, q, k, v, mask):
        query = self.w_q(q)
        key = self.w_k(k)
        value = self.w_v(v)

        # (batch, seq_len, d_model) -> (batch, h, seq_len, d_k)
        query = query.view(query.shape[0], query.shape[1], self.h, self.d_k).transpose(1, 2)
        key = key.view(key.shape[0], key.shape[1], self.h, self.d_k).transpose(1, 2)
        value = value.view(value.shape[0], value.shape[1], self.h, self.d_k).transpose(1, 2)

        x, self.attention_scores = attention(query, key, value, mask, self.dropout)

        # (batch, h, seq_len, d_k) -> (batch, seq_len, d_model)
        x = x.transpose(1, 2).contiguous().view(x.shape[0], -1, self.h * self.d_k)
        return self.w_o(x)

The key implementation gotcha here is the reshape sequence. Projecting to d_model and then viewing it as (h, d_k) — rather than running h separate smaller linear layers — is mathematically equivalent but dramatically more efficient: it’s one big matmul instead of h small ones, which matters a lot for GPU utilization. The .contiguous() call before the final .view() is not optional — .transpose() returns a view with non-contiguous memory layout, and .view() requires contiguous memory, so skipping this raises a runtime error (or silently wrong behavior if you use .reshape() instead, which will implicitly copy).

Why multiple heads at all, rather than one d_model-dimensional attention? Splitting into h heads of dimension d_k = d_model/h lets each head learn to attend using a different projection subspace — empirically, different heads specialize (some track short-range syntactic relations, others longer-range or positional patterns). A single full-size attention head, by contrast, is forced to average all such patterns into one attention distribution per query.

5. Position-wise Feed-Forward Network

class FeedForwardBlock(nn.Module):
    def __init__(self, d_model: int, d_ff: int, dropout: float):
        super().__init__()
        self.linear_1 = nn.Linear(d_model, d_ff)
        self.dropout = nn.Dropout(dropout)
        self.linear_2 = nn.Linear(d_ff, d_model)

    def forward(self, x):
        return self.linear_2(self.dropout(torch.relu(self.linear_1(x))))

This block is applied identically and independently to every position — there’s no mixing across the sequence dimension here (that’s entirely attention’s job). d_ff is typically 4× d_model (2048 vs 512 in the base config); the expand-then-contract shape gives the model extra capacity to transform each token’s representation nonlinearly, in between the sequence-mixing steps that attention provides.

6. Residual Connections & Normalization

class ResidualConnection(nn.Module):
    def __init__(self, dropout: float):
        super().__init__()
        self.dropout = nn.Dropout(dropout)
        self.norm = LayerNormalization()

    def forward(self, x, sublayer):
        return x + self.dropout(sublayer(self.norm(x)))  # Pre-LN
        # Post-LN alternative: return self.norm(x + self.dropout(sublayer(x)))

6.1 Post-LN vs Pre-LN

The original paper uses Post-LN: LayerNorm(x + Sublayer(x)). Normalization is applied after the residual addition, on the combined output.

Pre-LN instead normalizes the input to the sublayer, and adds the raw (unnormalized) sublayer output to the residual stream: x + Sublayer(LayerNorm(x)).

The practical difference is about gradient flow through depth. In Post-LN, every residual addition is immediately followed by a normalization that rescales the combined signal — this means the identity path (the raw residual x) gets its scale altered at every single layer, and gradients backpropagating through N stacked layers pass through N layer-norm rescalings, each of which can shrink or distort gradient magnitude. This is why the original Transformer needed a careful learning-rate warmup — without it, Post-LN training is prone to divergence or requires very conservative LR at the start, because early in training the layer norm statistics themselves are still stabilizing.

In Pre-LN, the residual stream itself is never renormalized — x passes through unchanged at every layer, and only the input to each sublayer is normalized. This gives you a clean, unimpeded identity path from the first layer to the last, which is much closer to the “gradient superhighway” property that made vanilla ResNets easy to train. Pre-LN models are empirically far more robust to learning rate choice and are noticeably more forgiving of skipping or shortening warmup — which is exactly the interaction we test in the ablation below. The tradeoff is that Pre-LN networks tend to have slightly worse final performance at a given depth if warmup is properly tuned for Post-LN — Post-LN’s forced renormalization can act as an implicit regularizer once training is stable — so this isn’t a strictly-better-in-every-way swap, more a stability/performance tradeoff.

6.2 Dropout Placement

Dropout in this implementation is applied in three distinct places, each for a different reason:

  1. After adding positional encoding to embeddings — regularizes the input representation itself.
  2. On attention weights, inside the attention() function, after softmax — randomly zeroes out some attention connections, discouraging the model from over-relying on any single key for a given query.
  3. On each sublayer’s output, before it’s added back to the residual stream — regularizes the update to the residual stream rather than the stream itself, which is important: dropout is never applied directly to the residual path x, only to what’s being added to it. Dropping the residual path itself would destroy the identity-mapping property that makes residual networks trainable.

7. Encoder & Decoder Stack Assembly

class EncoderBlock(nn.Module):
    def __init__(self, self_attention_block, feed_forward_block, dropout: float):
        super().__init__()
        self.self_attention_block = self_attention_block
        self.feed_forward_block = feed_forward_block
        self.residual_connections = nn.ModuleList([ResidualConnection(dropout) for _ in range(2)])

    def forward(self, x, src_mask):
        x = self.residual_connections[0](x, lambda x: self.self_attention_block(x, x, x, src_mask))
        x = self.residual_connections[1](x, self.feed_forward_block)
        return x


class DecoderBlock(nn.Module):
    def __init__(self, self_attention_block, cross_attention_block, feed_forward_block, dropout: float):
        super().__init__()
        self.self_attention_block = self_attention_block
        self.cross_attention_block = cross_attention_block
        self.feed_forward_block = feed_forward_block
        self.residual_connections = nn.ModuleList([ResidualConnection(dropout) for _ in range(3)])

    def forward(self, x, encoder_output, src_mask, tgt_mask):
        x = self.residual_connections[0](x, lambda x: self.self_attention_block(x, x, x, tgt_mask))
        x = self.residual_connections[1](x, lambda x: self.cross_attention_block(x, encoder_output, encoder_output, src_mask))
        x = self.residual_connections[2](x, self.feed_forward_block)
        return x

Note the decoder’s cross-attention call: query = x (decoder’s own state) but key = value = encoder_output. This is exactly where the encoder’s representation of the source sequence gets injected into the decoder — the decoder is asking “given what I’ve generated so far, which parts of the source sequence are relevant right now,” and the mask used here is the src_mask (padding mask on the source), not the causal mask — causality only applies to the decoder’s self-attention over its own generated tokens.

Both encoder and decoder stacks apply a final LayerNorm after the last block, since with Pre-LN the residual stream is otherwise unnormalized all the way through — without this final norm, the output fed to the projection layer would have unbounded/unnormalized scale.

8. Training Setup

8.1 Label Smoothing

Rather than training with a hard one-hot target distribution, label smoothing spreads a small amount of probability mass (typically ε=0.1) across the non-target vocabulary:

target_distribution[correct_token] = 1 - ε
target_distribution[other_tokens] = ε / (vocab_size - 1)

This discourages the model from becoming overconfident — pushing logits to extreme values to drive the softmax output arbitrarily close to 1.0 for the correct token. Overconfidence hurts both calibration (the model’s confidence no longer reflects its actual accuracy) and, counterintuitively, BLEU-style generation metrics, since an overconfident model commits harder to early mistakes during beam search.

8.2 Learning Rate Schedule (Noam Schedule)

lr = d_model ** (-0.5) * min(step_num ** (-0.5), step_num * warmup_steps ** (-1.5))

This increases LR linearly for the first warmup_steps, then decays proportionally to the inverse square root of the step number. The warmup phase exists specifically to get past the early-training instability discussed in §6.1 — at initialization, Post-LN’s normalization statistics are not yet representative, and large early updates under a high LR can push the model into a bad region it doesn’t recover from. Warmup keeps early updates small while those statistics stabilize, then ramps up once the model is on firmer footing.

8.3 Loss Masking

Padding tokens in the target sequence must be excluded from the loss — otherwise the model is rewarded for correctly predicting <pad> after <pad>, which is a trivial, meaningless pattern that would dilute the actual training signal:

loss_fn = nn.CrossEntropyLoss(ignore_index=pad_token_id, label_smoothing=0.1)

9. Ablation Study: Pre-LN vs Post-LN × Flat LR vs Warmup+Decay

The claim in §6.1 — that Pre-LN is more robust to LR schedule while Post-LN needs warmup — is widely repeated but worth actually testing rather than taking on faith. Setup: a 2×2 grid crossing normalization placement (Pre-LN / Post-LN) with LR schedule (flat constant LR / Noam warmup+decay), all other hyperparameters held fixed (same d_model, same number of layers/heads, same dataset, same number of steps, same seed where applicable).

Metrics tracked per cell: - Training loss curve (smoothed) - Gradient norm over time (particularly in the first few hundred steps) - Whether training diverges (loss → NaN/Inf) or plateaus early

Expected/observed pattern:

Flat LR Warmup + Decay
Post-LN Unstable early, high risk of divergence or requires very low flat LR to survive, which then undertrains Stable, matches paper’s reported behavior
Pre-LN Stable, converges reasonably even without warmup Stable, often marginally smoother early loss curve than flat LR, but the gap to flat-LR Pre-LN is much smaller than the corresponding gap for Post-LN

The interesting result isn’t just “warmup helps” — it’s the interaction: warmup’s benefit is much larger under Post-LN than under Pre-LN. That’s the direct empirical signature of the mechanism described in §6.1 — Pre-LN’s clean identity path makes the network far less sensitive to the exact shape of the LR schedule, because gradient magnitude isn’t being repeatedly rescaled by normalization layers stacked N deep.

10. Common Implementation Pitfalls

  • Forgetting the √d_model embedding scale — model still trains, but positional encoding dominates early representations, causing slower convergence.
  • Mask shape mismatches — attention masks need to broadcast correctly against (batch, h, seq_len, seq_len) attention score tensors; a mask shaped for a single head silently broadcasts wrong if you’re not careful with unsqueeze.
  • Off-by-one in decoder input/target shift — the decoder input at training time is the target sequence shifted right by one (prepended with <sos>), and the loss target is the unshifted sequence. Getting this backwards silently trains the model to copy rather than predict.
  • Using .view() after .transpose() without .contiguous() — covered in §4.2, raises a runtime error (or worse, silently wrong output with .reshape()).
  • Inconsistent dropout between train/eval — forgetting model.eval() before validation/inference leaves dropout active, adding noise to what should be deterministic generation.
  • Masking after softmax instead of before — leaves incorrect nonzero probability mass on masked positions unless you manually renormalize; masking with a large negative number before softmax handles this for free.

Large-magnitude inputs to softmax push it into saturated regions where the gradient is near zero almost everywhere except at the max — the softmax becomes nearly a hard argmax and gradients vanish for all the non-selected positions. Dividing by √d_k renormalizes the dot product back to unit variance regardless of d_k, keeping softmax in a well-conditioned regime.

**Masking**: `masked_fill_(mask == 0, -1e9)` happens *before* softmax, not after. Setting scores to a large negative number (rather than zero) ensures that after softmax, those positions get a weight of essentially exp(-1e9) ≈ 0 — masking after softmax would just leave the wrong probabilities in place and require manual renormalization.

### 4.2 Multi-Head Attention

```python
class MultiHeadAttentionBlock(nn.Module):
    def __init__(self, d_model: int, h: int, dropout: float):
        super().__init__()
        self.d_model = d_model
        self.h = h
        assert d_model % h == 0, "d_model must be divisible by h"
        self.d_k = d_model // h
        self.w_q = nn.Linear(d_model, d_model, bias=False)
        self.w_k = nn.Linear(d_model, d_model, bias=False)
        self.w_v = nn.Linear(d_model, d_model, bias=False)
        self.w_o = nn.Linear(d_model, d_model, bias=False)
        self.dropout = nn.Dropout(dropout)

    def forward(self, q, k, v, mask):
        query = self.w_q(q)
        key = self.w_k(k)
        value = self.w_v(v)

        # (batch, seq_len, d_model) -> (batch, h, seq_len, d_k)
        query = query.view(query.shape[0], query.shape[1], self.h, self.d_k).transpose(1, 2)
        key = key.view(key.shape[0], key.shape[1], self.h, self.d_k).transpose(1, 2)
        value = value.view(value.shape[0], value.shape[1], self.h, self.d_k).transpose(1, 2)

        x, self.attention_scores = attention(query, key, value, mask, self.dropout)

        # (batch, h, seq_len, d_k) -> (batch, seq_len, d_model)
        x = x.transpose(1, 2).contiguous().view(x.shape[0], -1, self.h * self.d_k)
        return self.w_o(x)
```

The key implementation gotcha here is the reshape sequence. Projecting to `d_model` and then *viewing* it as `(h, d_k)` — rather than running h separate smaller linear layers — is mathematically equivalent but dramatically more efficient: it's one big matmul instead of h small ones, which matters a lot for GPU utilization. The `.contiguous()` call before the final `.view()` is not optional — `.transpose()` returns a view with non-contiguous memory layout, and `.view()` requires contiguous memory, so skipping this raises a runtime error (or silently wrong behavior if you use `.reshape()` instead, which will implicitly copy).

Why multiple heads at all, rather than one d_model-dimensional attention? Splitting into h heads of dimension d_k = d_model/h lets each head learn to attend using a different projection subspace — empirically, different heads specialize (some track short-range syntactic relations, others longer-range or positional patterns). A single full-size attention head, by contrast, is forced to average all such patterns into one attention distribution per query.

## 5. Position-wise Feed-Forward Network

```python
class FeedForwardBlock(nn.Module):
    def __init__(self, d_model: int, d_ff: int, dropout: float):
        super().__init__()
        self.linear_1 = nn.Linear(d_model, d_ff)
        self.dropout = nn.Dropout(dropout)
        self.linear_2 = nn.Linear(d_ff, d_model)

    def forward(self, x):
        return self.linear_2(self.dropout(torch.relu(self.linear_1(x))))
```

This block is applied identically and independently to every position — there's no mixing across the sequence dimension here (that's entirely attention's job). d_ff is typically 4× d_model (2048 vs 512 in the base config); the expand-then-contract shape gives the model extra capacity to transform each token's representation nonlinearly, in between the sequence-mixing steps that attention provides.

## 6. Residual Connections & Normalization

```python
class ResidualConnection(nn.Module):
    def __init__(self, dropout: float):
        super().__init__()
        self.dropout = nn.Dropout(dropout)
        self.norm = LayerNormalization()

    def forward(self, x, sublayer):
        return x + self.dropout(sublayer(self.norm(x)))  # Pre-LN
        # Post-LN alternative: return self.norm(x + self.dropout(sublayer(x)))
```

### 6.1 Post-LN vs Pre-LN

The original paper uses **Post-LN**: `LayerNorm(x + Sublayer(x))`. Normalization is applied *after* the residual addition, on the combined output.

**Pre-LN** instead normalizes the input to the sublayer, and adds the raw (unnormalized) sublayer output to the residual stream: `x + Sublayer(LayerNorm(x))`.

The practical difference is about gradient flow through depth. In Post-LN, every residual addition is immediately followed by a normalization that rescales the combined signal — this means the identity path (the raw residual `x`) gets its scale altered at every single layer, and gradients backpropagating through N stacked layers pass through N layer-norm rescalings, each of which can shrink or distort gradient magnitude. This is why the original Transformer needed a *careful learning-rate warmup* — without it, Post-LN training is prone to divergence or requires very conservative LR at the start, because early in training the layer norm statistics themselves are still stabilizing.

In Pre-LN, the residual stream itself is never renormalized — `x` passes through unchanged at every layer, and only the *input* to each sublayer is normalized. This gives you a clean, unimpeded identity path from the first layer to the last, which is much closer to the "gradient superhighway" property that made vanilla ResNets easy to train. Pre-LN models are empirically far more robust to learning rate choice and are noticeably more forgiving of skipping or shortening warmup — which is exactly the interaction we test in the ablation below. The tradeoff is that Pre-LN networks tend to have slightly worse final performance at a given depth if warmup is properly tuned for Post-LN — Post-LN's forced renormalization can act as an implicit regularizer once training is stable — so this isn't a strictly-better-in-every-way swap, more a stability/performance tradeoff.

### 6.2 Dropout Placement

Dropout in this implementation is applied in three distinct places, each for a different reason:

1. **After adding positional encoding to embeddings** — regularizes the input representation itself.
2. **On attention weights**, inside the `attention()` function, after softmax — randomly zeroes out some attention connections, discouraging the model from over-relying on any single key for a given query.
3. **On each sublayer's output**, before it's added back to the residual stream — regularizes the *update* to the residual stream rather than the stream itself, which is important: dropout is never applied directly to the residual path `x`, only to what's being added to it. Dropping the residual path itself would destroy the identity-mapping property that makes residual networks trainable.

## 7. Encoder & Decoder Stack Assembly

```python
class EncoderBlock(nn.Module):
    def __init__(self, self_attention_block, feed_forward_block, dropout: float):
        super().__init__()
        self.self_attention_block = self_attention_block
        self.feed_forward_block = feed_forward_block
        self.residual_connections = nn.ModuleList([ResidualConnection(dropout) for _ in range(2)])

    def forward(self, x, src_mask):
        x = self.residual_connections[0](x, lambda x: self.self_attention_block(x, x, x, src_mask))
        x = self.residual_connections[1](x, self.feed_forward_block)
        return x


class DecoderBlock(nn.Module):
    def __init__(self, self_attention_block, cross_attention_block, feed_forward_block, dropout: float):
        super().__init__()
        self.self_attention_block = self_attention_block
        self.cross_attention_block = cross_attention_block
        self.feed_forward_block = feed_forward_block
        self.residual_connections = nn.ModuleList([ResidualConnection(dropout) for _ in range(3)])

    def forward(self, x, encoder_output, src_mask, tgt_mask):
        x = self.residual_connections[0](x, lambda x: self.self_attention_block(x, x, x, tgt_mask))
        x = self.residual_connections[1](x, lambda x: self.cross_attention_block(x, encoder_output, encoder_output, src_mask))
        x = self.residual_connections[2](x, self.feed_forward_block)
        return x
```

Note the decoder's cross-attention call: `query = x` (decoder's own state) but `key = value = encoder_output`. This is exactly where the encoder's representation of the source sequence gets injected into the decoder — the decoder is asking "given what I've generated so far, which parts of the source sequence are relevant right now," and the *mask* used here is the `src_mask` (padding mask on the source), not the causal mask — causality only applies to the decoder's self-attention over its own generated tokens.

Both encoder and decoder stacks apply a final LayerNorm after the last block, since with Pre-LN the residual stream is otherwise unnormalized all the way through — without this final norm, the output fed to the projection layer would have unbounded/unnormalized scale.

## 8. Training Setup

### 8.1 Label Smoothing

Rather than training with a hard one-hot target distribution, label smoothing spreads a small amount of probability mass (typically ε=0.1) across the non-target vocabulary:

```
target_distribution[correct_token] = 1 - ε
target_distribution[other_tokens] = ε / (vocab_size - 1)
```

This discourages the model from becoming *overconfident* — pushing logits to extreme values to drive the softmax output arbitrarily close to 1.0 for the correct token. Overconfidence hurts both calibration (the model's confidence no longer reflects its actual accuracy) and, counterintuitively, BLEU-style generation metrics, since an overconfident model commits harder to early mistakes during beam search.

### 8.2 Learning Rate Schedule (Noam Schedule)

```python
lr = d_model ** (-0.5) * min(step_num ** (-0.5), step_num * warmup_steps ** (-1.5))
```

This increases LR linearly for the first `warmup_steps`, then decays proportionally to the inverse square root of the step number. The warmup phase exists specifically to get past the early-training instability discussed in §6.1 — at initialization, Post-LN's normalization statistics are not yet representative, and large early updates under a high LR can push the model into a bad region it doesn't recover from. Warmup keeps early updates small while those statistics stabilize, then ramps up once the model is on firmer footing.

### 8.3 Loss Masking

Padding tokens in the target sequence must be excluded from the loss — otherwise the model is rewarded for correctly predicting `<pad>` after `<pad>`, which is a trivial, meaningless pattern that would dilute the actual training signal:

```python
loss_fn = nn.CrossEntropyLoss(ignore_index=pad_token_id, label_smoothing=0.1)
```

## 9. Ablation Study: Pre-LN vs Post-LN × Flat LR vs Warmup+Decay

The claim in §6.1 — that Pre-LN is more robust to LR schedule while Post-LN needs warmup — is widely repeated but worth actually testing rather than taking on faith. Setup: a 2×2 grid crossing normalization placement (Pre-LN / Post-LN) with LR schedule (flat constant LR / Noam warmup+decay), all other hyperparameters held fixed (same d_model, same number of layers/heads, same dataset, same number of steps, same seed where applicable).

**Metrics tracked per cell:**
- Training loss curve (smoothed)
- Gradient norm over time (particularly in the first few hundred steps)
- Whether training diverges (loss → NaN/Inf) or plateaus early

**Expected/observed pattern:**

| | Flat LR | Warmup + Decay |
|---|---|---|
| **Post-LN** | Unstable early, high risk of divergence or requires very low flat LR to survive, which then undertrains | Stable, matches paper's reported behavior |
| **Pre-LN** | Stable, converges reasonably even without warmup | Stable, often marginally smoother early loss curve than flat LR, but the gap to flat-LR Pre-LN is much smaller than the corresponding gap for Post-LN |

The interesting result isn't just "warmup helps" — it's the *interaction*: warmup's benefit is much larger under Post-LN than under Pre-LN. That's the direct empirical signature of the mechanism described in §6.1 — Pre-LN's clean identity path makes the network far less sensitive to the exact shape of the LR schedule, because gradient magnitude isn't being repeatedly rescaled by normalization layers stacked N deep.

If you're stuck maintaining a Post-LN architecture for legacy or specific-performance reasons, the warmup schedule isn't a nice-to-have, it's close to a hard requirement at this depth.

## 10. Common Implementation Pitfalls

- **Forgetting the √d_model embedding scale** — model still trains, but positional encoding dominates early representations, causing slower convergence.
- **Mask shape mismatches** — attention masks need to broadcast correctly against `(batch, h, seq_len, seq_len)` attention score tensors; a mask shaped for a single head silently broadcasts wrong if you're not careful with `unsqueeze`.
- **Off-by-one in decoder input/target shift** — the decoder input at training time is the target sequence shifted right by one (prepended with `<sos>`), and the loss target is the *unshifted* sequence. Getting this backwards silently trains the model to copy rather than predict.
- **Using `.view()` after `.transpose()` without `.contiguous()`** — covered in §4.2, raises a runtime error (or worse, silently wrong output with `.reshape()`).
- **Inconsistent dropout between train/eval** — forgetting `model.eval()` before validation/inference leaves dropout active, adding noise to what should be deterministic generation.
- **Masking after softmax instead of before** — leaves incorrect nonzero probability mass on masked positions unless you manually renormalize; masking with a large negative number before softmax handles this for free.
